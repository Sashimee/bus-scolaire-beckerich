## Relancer les tests du serveur après redémarrage

**La base était temporaire et a disparu** : elle vivait sous `/tmp`, effacé au reboot.
Cette machine n'a ni Docker, ni PostgreSQL, ni `sudo` — sans base, **88 tests sur 162 se
sautent en silence**, et ce sont ceux de l'authentification, des capacités, de la
limitation de débit, du SQL et du journal. C'est en les lançant qu'on a découvert qu'un
test de sécurité était faux : ne pas s'en passer.

```bash
# hors du dépôt — n'ajoute aucune dépendance au projet
mkdir -p /tmp/pg && cd /tmp/pg && npm init -y && npm install embedded-postgres
BIN=$PWD/node_modules/@embedded-postgres/linux-x64/native/bin
export LD_LIBRARY_PATH=$PWD/node_modules/@embedded-postgres/linux-x64/native/lib
$BIN/initdb -D data -U bus --auth=trust -E UTF8

# `-k` court et obligatoire : un chemin de socket Unix ne peut pas dépasser 107 octets,
# et celui du répertoire de travail temporaire le dépasse largement. Piège déjà payé.
mkdir -p /tmp/pgsock
$BIN/pg_ctl -D data -l pg.log -o "-p 5433 -k /tmp/pgsock" start

# créer la base « bus » (pas de psql dans ce paquet — passer par le client node)
cd /home/alex/projects/bus-scolaire-beckerich/serveur
node -e "import('postgres').then(async({default:p})=>{const s=p('postgres://bus@127.0.0.1:5433/postgres');await s\`create database bus\`.catch(()=>{});await s.end()})"

# et enfin
DATABASE_URL_TEST=postgres://bus@127.0.0.1:5433/bus npm test
```

Pour l'arrêter : `$BIN/pg_ctl -D /tmp/pg/data stop`.

## Remarques de fond, à ne pas perdre

**Un test qu'on n'a jamais vu échouer n'est pas encore un test.** Quatre gardes s'étaient
éteintes sans bruit et personne ne l'avait remarqué : le contrôle des chaînes vides
comparait `[]` à `[]` dans les quatre langues depuis toujours ; il n'existait plus aucun
test de contraste depuis R49 ; le test de R59 n'exerçait pas l'exploit qu'il prétendait
couvrir ; et R58 n'était gardée nulle part au niveau de la route. Les deux derniers ne se
sont vus **qu'après** avoir donné une vraie base au serveur.

**Ma première version du test de contraste passait la mutation.** Elle recopiait la liste
des couples au lieu de lire la feuille : elle mesurait la palette, pas le CSS. Remettre
`color: var(--danger)` sur `.bouton--danger:hover` ne la faisait pas tomber. Elle lit
maintenant les règles des boutons dans `index.css` — c'est ce qui la rend réelle.

**Attention à `git checkout -- <fichier>` pendant une vérification par mutation** : il
efface aussi le correctif non commité. Ça m'est arrivé deux fois. Copier le fichier dans
le scratchpad avant de le muter, et restaurer depuis la copie.

**Les données dont la brochure est la source n'ont pas été « corrigées ».** Vitesses
impossibles, dissymétrie des bus, position du précoce : ce sont des questions à poser, pas
des valeurs à réécrire. Elles sont désormais signalées par `validerPlan` ou inscrites en
réserve — jamais devinées. C'est le second principe du projet appliqué aux données
elles-mêmes.
